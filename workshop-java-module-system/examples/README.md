# Java Module System - Workshop

The [OpenJDK project Jigsaw](https://openjdk.org/projects/jigsaw/) introduced
the concept of modules which provide stronger encapsulation. The Java Module
System addresses shortcomings, such as split package and missing classes at
runtime, that the traditional approach (the class-path) is subject to. While the
benefits of this project are many, the Java Module System is still misunderstood
and rarely used. This workshop tries to demystify the Java Module System and
provides examples showing how the Java Module System works and how this can be
integrated with existing projects.

## Java Module System Reference

### `java` (Running Modules)

- `java --module-path <PATH>` or `java -p <PATH>`: Specifies where modules are
  located (either directories or JAR files).
- `java --module <module>/<MainClass>` or `java -m <module>/<MainClass>`:
  Executes the specified module’s main class.
- `java --add-modules <modules>`: Explicitly adds modules that are not resolved
  automatically (e.g., `ALL-SYSTEM`).
- `java --add-modules ALL-MODULE-PATH`: Adds all modules found on the module
  path.
- `java --list-modules`: Lists all observable modules on the module path and in
  the runtime image.
- `java --describe-module <module>`: Displays detailed information about a given
  module (e.g., exported packages, required modules).
- `java --show-module-resolution`: Prints diagnostic information about how
  modules are resolved.
- `java --add-opens <module>/<package>=<target>`: Opens the specified package in
  the given module to the target module for deep reflection at runtime.
- `java --add-opens <module>/<package>=ALL-UNNAMED`: Opens the specified package
  to all unnamed modules for deep reflection.
- `java --add-exports <module>/<package>=<target>`: Exports the specified
  package from a named module to a target module at runtime.
- `java --add-exports <module>/<package>=ALL-UNNAMED`: Exports the specified
  package to all unnamed modules at runtime.
- `java --add-reads <module>=<target>[,<target>]`: Allows a module to read
  (depend on) additional target modules at runtime.
- `java --add-reads <module>=ALL-UNNAMED`: Allows a module to read all unnamed
  modules at runtime.

### `javac` (Compiling Modules)

- `javac --module-path <PATH>` or `javac -p <PATH>`: Specifies where required
  modules are located during compilation.
- `javac -d <DIR>`: Outputs compiled classes to the specified directory
  (commonly used when creating a modular directory structure).
- `javac --module <module>(,<module>...)`: Compiles multiple modules from a
  structured source tree.

### `jar` (Packaging Modules)

- `jar --create --file <JAR> --main-class <Main> -C <DIR> .`: Packages classes
  and sets the executable main class.
- `jar --describe-module --file <JAR>`: Displays the module’s metadata. Use
  `--release <version>` when producing multi-release JARs.
- `jar --print-module-descriptor --file <JAR>`: Prints the compiled
  `module-info.class` descriptor.
- `unzip -p <JAR> META-INF/MANIFEST.MF`: Prints the JAR manifest without
  extracting the archive.

### `jmod` (Creating `.jmod` Files for JDK Tools)

- `jmod create --class-path <PATH> <FILE.jmod>`: Creates a JMOD file.
- `jmod describe <FILE.jmod>`: Displays module information contained in the
  JMOD.

### `jlink` (Building a Custom Runtime Image)

- `jlink --module-path <PATH>`: Specifies where to locate modules.
- `--add-modules <modules>`: Selects which modules to include in the runtime image.
- `--output <DIR>`: Defines the output directory for the generated runtime image.

### `jpackage` (Distributing Applications)

- `--name <appname>`: Names the application.
- `--input <dir>`: Directory containing application modules/JARs.
- `--main-jar <JAR>`: Specifies the entry-point JAR.
- `--main-class <MainClass>`: Specifies the application’s main class.
- `--type <pkg>`: Selects the installer or package type (e.g., `exe`, `dmg`,
  `rpm`).

## Common Commands

1. Build all projects

   Please note that some tests require external dependencies that are not
   managed by Maven and will fail if not provided. That’s why these tests are
   skipped in the following example.

   ```shell
   ./mvnw clean package -DskipTests
   ```

2. Run a goal for a specific project

   ```
   ./mvnw <goal> [<goal>*] --projects <project> [<args>*]
   ```

   Example:

   ```shell
   ./mvnw clean package --projects 'simple-hello-world-application-with-modules'
   ```

3. Update dependencies and plugins

   ```shell
   mkdir -p './target'
   ./mvnw versions:display-plugin-updates > './target/plugin-updates.txt'
   ./mvnw versions:display-dependency-updates > './target/dependency-updates.txt'
   ```
